Warum ein Skills Hub?

Euer Team pflegt seine Skills an einem Ort, ohne sie global zu aktivieren. Wählt für ein Java-Projekt den Java-Workflow aus: Der Hub installiert die dazugehörigen Skills gleich mit. Python-Skills bleiben draußen.

Checkt die installierten Skills ins Projekt-Repo ein, damit alle mit demselben Stand arbeiten. Änderungen im Hub landen erst im Projekt, wenn ihr sie bewusst übernehmt.

Im Projekt installieren

Der Hub ersetzt nur seine eigenen, ausgewählten Skill-Ordner.

Kopiere den gesamten Block und füge ihn im Projektstamm in Bash ein.

Nach der Installation

Rufe einen Skill mit /skill-name auf. /skills zeigt die verfügbaren Skills.

Claude Code erkennt lokale Änderungen in der laufenden Sitzung. Fehlt ein Skill, führe /reload-skills aus.

Erwähne den Skill mit @skill-id im Prompt. Das /-Menü zeigt Commands, keine Skills. Die registrierten Skills siehst du im Projektterminal mit opencode api skill.list.

Fehlt ein Skill in OpenCode V2, lade die Konfiguration mit /reload oder im Terminal mit opencode reload neu. Wenn das nicht hilft, kannst du den lokalen Hintergrunddienst mit opencode service restart neu starten.

Erwähne den Skill mit $skill-name im Prompt. /skills oder die Eingabe von $ öffnet die Skill-Auswahl.

Codex erkennt neue und geänderte Skills automatisch. Fehlt ein Skill, starte Codex neu.
